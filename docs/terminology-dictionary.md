# Terminology Dictionary

## Overview

This document defines the standard Indonesian terminology to be used consistently throughout the Attendance Management System. Each business concept has exactly one canonical Indonesian term, ensuring a coherent user experience.

## Purpose

- Enforce consistent terminology across all UI elements, documentation, and code
- Eliminate confusion from multiple terms for the same concept
- Provide clear guidance for developers and translators
- Support proper internationalization with one-to-one mappings

## Usage Guidelines

### 1. Consistency Rules

- **Always use the standard term** specified in this dictionary
- **Never use deprecated terms** in new code or UI
- **Replace deprecated terms** when updating existing code
- **Maintain one-to-one mappings** for navigation terms

### 2. Naming Conventions

- Use **sentence case** for labels: "Nama karyawan" not "Nama Karyawan"
- Use **title case** for page titles: "Manajemen Karyawan"
- Avoid abbreviations unless widely understood (e.g., "ID" is acceptable, "Tgl" should be "Tanggal")

### 3. Tone and Style

- Use **formal but friendly** tone: "Nama wajib diisi" not "Nama harus diisi dong"
- Use **active voice**: "Sistem berhasil menyimpan data" not "Data telah disimpan"
- Avoid mixing Indonesian and English in a single phrase

### 4. Adding New Terms

When adding new terms to this dictionary:

1. Check if a similar concept already exists
2. Ensure the term is professional and widely understood
3. Verify uniqueness for navigation terms
4. Add both Indonesian and English translations
5. Include usage notes if the term has specific context

### 5. Translation Key Naming

Translation keys should follow this pattern:

- Navigation: `nav.{concept}` (e.g., `nav.home`, `nav.dashboard`)
- Forms: `form.label.{field}` (e.g., `form.label.name`, `form.label.email`)
- Buttons: `button.{action}` (e.g., `button.save`, `button.cancel`)
- Messages: `message.{type}.{action}` (e.g., `message.success.save`, `message.error.not_found`)
- Alerts: `alert.{type}` (e.g., `alert.confirm_delete`, `alert.confirm_save`)
- DataTables: `datatable.{element}` (e.g., `datatable.search`, `datatable.showing`)
- Validation: `validation.{rule}` (e.g., `validation.required`, `validation.email`)

## Maintenance

This dictionary should be updated when:

- New business concepts are introduced
- User feedback indicates terminology confusion
- Deprecated terms are found in the codebase
- New UI sections require standardized terms

All updates must maintain consistency with existing terms and follow the guidelines above.
